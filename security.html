Security & Privacy

Written for the people who get asked "is this safe to use in class?" — educators, IT reviewers, and data protection teams. The short version: The Disruptor collects no personal data at all, and every claim on this page can be verified by reading the source code.

No personal data is processed.

The Disruptor is a single HTML file that runs entirely in the player's browser. No accounts, no logins, no cookies, no analytics, no tracking, and no data transmitted to game servers — there are none. Game state exists only in the player's browser and vanishes with the tab.

For university IT and data protection teams

  • No personal data collected. No names, email addresses, student numbers, or accounts. Under GDPR there is nothing to assess: no consent banner, DPIA, or processor agreement is needed.
  • No cookies or tracking. The game and this website set no cookies and run no analytics or advertising trackers.
  • No integration with university systems. No LMS connection, no student authentication, no licences to procure. Students simply open a web page.
  • Fully auditable. The complete source code is open source and public on GitHub, so every claim here can be checked by inspection.
  • Offline option. Institutions preferring zero network activity can download the HTML file and run it locally or from their own servers.

The CEO reflection tool (Katrien)

The game links to an optional reflection tool built on Claude artefacts, in which players can discuss their end-of-game report with the fictional CEO. Using it requires a free Claude account, and the player chooses to upload their own report PDF to Claude (Anthropic) — in the same way they might paste text into any AI assistant. The game itself transmits nothing, and the tool is entirely skippable.

Security practices

The project repository has GitHub's security features enabled, including private vulnerability reporting, secret scanning, and code scanning. The account is protected with two-factor authentication and the site is served over enforced HTTPS.

Reporting a vulnerability

If you find a security issue, please report it responsibly to ammon.salter@wbs.ac.uk
